### Task 2 implementation contract

- Add `USAGE_CAPTURE_UPSTREAMS` as an optional JSON map keyed by supported managed runtime (`codex`, `claude_code`). Reject `hermes` until its actual ACP endpoint path is verified. Values declare `baseUrl`, wire `protocol` (`responses` for Codex, `anthropic_messages` for Claude) and required `apiKeyEnv` (an environment variable name only). The reusable protocol layer also supports `chat_completions`. This first automatic HTTP contract uses explicitly configured API keys. No credentials in the map. Validate complete configuration before startup; allow HTTPS and loopback HTTP, reject URL credentials/fragments/query, protocol/provider mismatches and unknown fields. Empty map keeps existing runtime configuration unchanged.
- Relay listens only on loopback with unguessable per-Session/epoch route tokens, forwards only to that token's fixed configured upstream, and never follows HTTP redirects. Forward request bodies and SSE response bytes transparently with backpressure; remove hop-by-hop headers. Abort upstream when downstream aborts; close owned sockets/requests on shutdown. Unrecognized endpoints can pass through to the fixed upstream but are never normalized as usage. Do not expose route tokens or upstream credentials in public API/logs.
- Default runtime wiring: Codex API-key custom model provider via the installed codex-acp `CODEX_CONFIG` override, `wire_api=responses`, `supports_websockets=false`; Claude via `ANTHROPIC_BASE_URL`; Hermes custom endpoint configuration only if its actual ACP configuration path is verified. Providers receive only a local opaque credential; the relay strips incoming authentication/cookies and sets the fixed upstream API credential named by `apiKeyEnv` from service memory. Never copy real upstream keys into commands or Provider configs. Clear or reject conflicting credential/routing selectors, including Claude Bedrock/Vertex and Hermes provider overrides. Probes must not fabricate Session captures. Only mutate managed Provider homes; preserve unrelated config. Native OAuth/Bedrock/Vertex routing and arbitrary Provider-internal model calls are outside this first HTTP contract; surface unsupported/no-observed-capture states rather than claiming coverage.
- Keep HTTP forwarding reusable and independent of business tables. Put host binding/enrichment and runtime configuration in adapters. Node built-ins suffice; use the already-installed YAML parser for managed Hermes configuration if needed. Refactor the existing snapshot normalizer for direct in-memory canonical exchanges instead of requiring file serialization. Preserve manual `context-snapshot-v1` import compatibility.
- Decode supported HTTP content encodings on an observation copy with bounded decompressed output, leaving original forwarded bytes intact. Node 22.16 provides gzip/deflate/brotli/zstd in `node:zlib` (verified locally); zstd is relevant to Codex request compression. Unknown encodings or decompression failures remain explicit capture gaps. Do not silently lose every compressed request in an otherwise advertised protocol path.
- Normalize non-stream JSON plus Responses `response.completed`, Chat streaming usage, Anthropic `message_start` plus `message_delta`/`message_stop`. Usage is cumulative within one response, never sum repeated stream snapshots. Retain native response identity for replay and native-log reconciliation. Change BOTH Claude native-log and capture canonical identity to `claude-message:<message.id>` within the frozen business epoch (requestId can be ancillary metadata); missing message IDs remain unresolved, never merged by timestamp or token equality. Terminal stream loss stays partial/interim. Repeated content in two distinct model requests stays two exposures. Never generate fictitious request counts from cumulative Codex intervals.
- Persist capture-intent/health metadata so failed/aborted/truncated/unsupported captures and crash interruptions remain visible in `/api/usage/summary`. Runtime registration but no observed traffic means waiting/unverified, not complete. Bound request/response retention, event size, per-session call identity cache and active work; limits downgrade capture while forwarding remains functional. No raw bodies, authorization headers or raw tool arguments/results in SQLite or logs. Tests must inspect persistence for synthetic sentinel leakage.
- Use actual projected MCP server identities and observed runtime names to produce the same `mcp:<serverId>:<toolName>` identity as the wrapper, keeping distinct servers distinct. Explicit native tool-call evidence can map names; do not guess from display titles. Per-call arguments containing a confirmed Skill path can tag only that call's argument/result exposure with Skill and known plugin ownership. Persist only identity/tag metadata needed for later result association; plain Read calls outside Skill paths remain ordinary tools. Definitions get tool ownership, never blanket Skill attribution.
- Capture binding freezes Session generation, epoch and current Run at request start. Revalidate generation/epoch before persisting late completions, so reset/delete cannot repopulate old subjects or contaminate a new Run. Drain accepted work before maintenance clears provider state and close capture after runtime producers stop. Capture processing failure must not turn an otherwise successful model response into a failed Run.
- Capture API keys must not leak through inherited child environment either: service boot currently removes management/smoke keys via `removeServiceSecretsFromEnvironment`, while acpx inherits the remaining process environment. Retain configured capture secrets in service-owned memory and scrub their named variables before untrusted Provider/project children launch; do not mutate unrelated credentials. Include this boundary in the runtime-path privacy test.
