# Remote Agent Server 管理台 UX 重构设计

## 目标

当前管理台把创建、列表、编辑、检查和详情内容堆在同一个页面。Agent 展开 Skills 后会直接渲染近百条记录；项目环境把所有仓库编辑表单同时展开；Session 列表也同时承担创建。随着功能增加，页面会持续变长，常用操作难以定位。

本次重构采用统一的资源型信息架构：列表页负责浏览和进入，新建页负责创建，详情页负责单个资源的管理。后端 API、数据库和现有业务语义保持不变。

## 技术选择

- 使用 shadcn/ui 作为 UI 组件框架，选择成熟的 Radix 基础组件和 Tailwind CSS 4。
- 使用 React Router 的声明式模式管理前端路由。
- 继续使用现有 React、Vite、TypeScript 和 Vitest，不引入 Next.js、状态管理框架或新的服务端渲染层。
- 只安装本次实际使用的 Sidebar、Button、Tabs、Card、Badge、Input、Select、Dialog、Alert Dialog、Table、Skeleton、Empty、Collapsible、Textarea 和 Tooltip 等组件，不安装整套模板或页面区块。
- 保留少量项目 CSS，用于品牌色、对话布局和运行轨迹等业务特有样式；通用控件、间距和响应式布局使用项目内的 shadcn 组件与 Tailwind 类。

选择 shadcn/ui 的首要原因是它对 Coding Agent 提供官方 Skill、MCP、CLI 和 Registry。Skill 会读取项目的 `components.json`，向 Agent 提供框架、别名、基础组件库、已安装组件和组合规则；MCP 可以搜索、查看并按需安装组件。组件源码直接保存在仓库中，Codex、Claude Code、Hermes 等 Agent 都能读取、修改和测试实际实现，不依赖对第三方封装内部行为的猜测。

项目初始化后提交 `components.json` 和生成的组件源码，并安装官方 shadcn Skill。MCP 作为开发工具按不同 Agent 的推荐方式配置，不把用户级凭证或全局配置提交到仓库。React Router 用于替换手写的 `pushState` 和路径判断，使每个功能页面都有稳定 URL。

## 全局结构

桌面端使用固定左侧导航，移动端折叠为顶部菜单。导航只保留三个一级资源：

- Agent
- 项目环境
- Session

连接状态和“断开”放在导航底部，不占用业务页面操作区。主内容区统一使用：面包屑、页面标题、简短说明、右上角主要动作。每个页面只出现一个主要动作。

## 路由与页面职责

### Agent

- `/agents`：Agent 列表。展示名称、Provider、项目环境和启用状态；整行进入详情；右上角只有“新建 Agent”。
- `/agents/new`：创建 Agent。仅包含名称、Provider、项目环境和提交操作。
- `/agents/:id`：概览。展示基本信息、启停状态和运行检查；检查结果留在概览页。
- `/agents/:id/skills`：Skills 管理。展示已启用数量、搜索、来源筛选、逐项启停和 ZIP 上传。
- `/agents/:id/settings`：设置。修改名称和项目环境；Provider 只读；删除放在独立危险区域。

Agent 详情页顶部固定显示名称、Provider 和状态，下面使用“概览 / Skills / 设置”页签导航。切换页签会改变 URL，刷新后仍保留当前位置。

### 项目环境

- `/project-environments`：项目环境列表。展示环境名称、项目数量、准备状态和当前版本；右上角只有“新建项目环境”。
- `/project-environments/new`：创建项目环境。
- `/project-environments/:id`：环境概览。展示准备状态、当前版本、最近检查、失败原因和“立即检查”。
- `/project-environments/:id/repositories`：项目管理。展示项目列表；新增和编辑时只打开一个表单弹窗，页面不同时展开所有输入框。

项目环境详情页使用“概览 / 项目”页签。准备中时，项目编辑操作禁用并明确说明原因；轮询只更新当前详情或列表数据，不改变用户所在页面。

### Session

- `/sessions`：Session 列表。展示标题、Agent、状态和更新时间；右上角只有“新建 Session”。
- `/sessions/new`：创建 Session。创建成功后进入新 Session。
- `/sessions/:id`：对话详情，专注多轮输入和回复。

Session 对话默认只展示用户输入、Agent 回复和 Run 终态。工具调用、状态事件、错误详情归入每轮下方的“执行轨迹”折叠区；失败时自动展开错误摘要。输入框继续固定在底部，运行中只保留“取消运行”这个关键动作。

## 列表与状态

- 列表使用紧凑卡片或表格，不在列表行内展开编辑表单或详情内容。
- 列表为空时给出对应的创建按钮，而不是只有说明文字。
- 请求加载中显示 Skeleton；失败显示就地 Alert 和重试按钮；成功操作使用短暂通知。
- 状态颜色保持一致：绿色表示可用或完成，黄色表示准备中或运行中，红色表示失败，灰色表示停用或未准备。
- 删除继续使用确认弹窗；已有 Session 的 Agent 仍不可删除，并给出停用建议。

## 响应式与可访问性

- 小屏幕导航折叠，列表改为卡片；详情页签允许横向滚动。
- 所有表单字段保持可见标签；图标按钮提供可访问名称。
- 键盘焦点、错误提示、加载状态和弹窗焦点管理使用 Radix 与 shadcn 组件的默认能力。
- 不使用只有颜色才能表达的状态，Badge 同时显示中文状态文字。

## 数据与组件边界

- 页面继续通过现有 `api` 方法访问后端，不改变接口。
- 为 Agent、项目环境分别建立详情布局组件，负责页头、Tabs 和 Outlet；具体页面只处理自身数据和操作。
- 列表页与详情页独立加载数据，不建立全局状态仓库。
- 共用 PageHeader、ResourceList、StatusBadge 和 LoadError 等少量业务组件；不重复封装 shadcn 已经生成到项目中的通用组件。

## 测试与验收

- 路由测试覆盖三个资源的列表、新建、详情和页签直达 URL。
- Agent 测试覆盖创建、检查、启停、Skill 搜索/启停/上传、设置和删除限制。
- 项目环境测试覆盖创建、概览检查、项目新增/编辑/删除和准备中禁用。
- Session 测试覆盖创建后跳转、对话、运行轨迹折叠、实时事件、取消和错误恢复。
- 保留后端 SPA 深层路由回退测试。
- 最终运行全量测试、类型检查和生产构建，并在本地浏览器验证桌面与窄屏的主要路径。

## 本次不做

- 不新增 Dashboard、统计图表、全局搜索或权限系统。
- 不修改后端 API、数据库或业务规则。
- 不引入服务端渲染、前端数据缓存框架或复杂状态管理。
- 不为了迁移保留旧页面结构；新路由直接替换旧实现。
