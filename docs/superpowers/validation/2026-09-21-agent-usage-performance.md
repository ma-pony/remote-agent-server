# Agent Usage 性能修复与验证

日期：2026-09-21。范围：此前性能审查的 6 项发现；在现有未提交功能分支上修复，无新生产依赖。没有使用生产数据库、真实 Provider 或外部业务服务。

## 修复结果

| 问题 | 修复 | 回归依据 |
| --- | --- | --- |
| MCP 完成事件读取完整会话历史 | 按主键读取调用基本信息，完成路径不进入归因详情查询 | 禁止 detail 调用的观察器测试、完成状态检查 |
| 日期筛选、排名、证据分页加载历史暴露 | SQL 过滤及聚合；持久化首次结果索引；证据先选有界上下文候选再生成当前页；估算元数据字典去重 | 日期不重置首次语义、迟到/修订/删除/重启、游标顺序、读取行数及 ID 计算预算 |
| 日志追加触发全量解析和逐条 checkpoint | 保存字节位置、行号、无正文解析状态；每批最多 100 条与 checkpoint 同事务提交 | 追加仅产生新观测、累计基线、多观测单行中断恢复、UTF-8 半行、无换行 EOF、失败恢复 |
| HTTP 调用缓存逐请求全部重写 | 只写新增/变化项和删除淘汰项；事务提交成功后才更新内存缓存 | 无变化零缓存写入、事务失败后重试、重启恢复与身份归属 |
| 相同词表多个 profile 重复实例化 | 按资产指纹共享引擎及纯计数缓存，profile 元数据独立 | 实际分词引擎调用、跨 Provider/profile 计量来源不串用 |
| MCP 票据历史增长 | 维护收尾后、删除 Session 时及移除 MCP Server 时撤销票据 | 收尾事件仍可提交、旧票据拒绝、保留 Server 和其他 Session 不受影响 |

前端排名排序、分页使用独立请求依赖，不重复加载汇总、趋势、来源；已有内容在排名刷新时保留。交互回归覆盖请求次数及显示状态。

独立审查还发现证据分页虽然只返回一页，仍在 LIMIT 前生成全部历史证据 ID。该问题已通过候选上下文 CTE 修复；预算测试先复现 200 次计算超过 10 次限制，再验证修复后的首页和后续游标页。独立审查未报告其他可执行的计量回归。

## 同工作负载前后对比

查询数据为 3,000 个模型上下文、60,000 条暴露；保留完整历史。以下为本机串行合成基准，单次耗时用于比较，不能等同生产 p95。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 全历史排名 | 1,506.4 ms | 227.6 ms |
| 只选最后一次请求的排名 | 942.3 ms | 3.1 ms |
| 无关联暴露的执行详情 | 543.5 ms | 0.6 ms |
| 最新请求的输入证据 | 598.7 ms | 0.6 ms |
| 全排名前后 heapUsed | 7.3 → 208.8 MiB | 7.4 → 7.5 MiB |
| 测试数据库文件 | 51.4 MiB | 49.2 MiB |
| 5,000 行日志后追加 1 行：输出观测 | 5,001 条 | 1 条 |
| 同一追加：SQL 行变更 / 耗时 | 5,005 / 397 ms | 5 / 8 ms |
| 2,048 项调用缓存：每个无工具请求的 SQL 行变更 | 4,101 | 5 |
| 同一请求：WAL 写入页 / 体积 | 115 / 0.45 MiB | 22 / 0.09 MiB |
| 相同词表两个 profile：GC 后堆 | 110.0 MiB | 61.9 MiB |

新增全历史证据首页基准：返回 51 条、耗时 2.9 ms，heapUsed 7.4 → 8.1 MiB。日志首次导入 5,000 条耗时 649 ms，不变文件采集 3 ms；追加后历史事件总数仍正确为 5,001。WAL 指标是写放大，不是永久净增长；查询前后内存包括尚未回收的临时分配，不表示长期泄漏。

## 验证方式与边界

- Node.js 22.16.0、macOS arm64；真实 better-sqlite3、磁盘 WAL、合成 Provider 日志和固定公开 Qwen 词表。基准串行运行，查询/词表进程显式 GC。
- `corepack pnpm test` 最终结果：77 个测试文件通过、1 个跳过；1,022 个用例通过、17 个跳过。覆盖前后端交互、API 边界、采集、迁移、维护及合成 HTTP/MCP 链路。`corepack pnpm typecheck`、`corepack pnpm build` 和 `git diff --check` 均通过。
- 一轮与类型检查并行的全量运行中，原有 MCP/Skill 页面各一次异步加载断言失败；两个文件单独复核 26 个用例通过，随后不与类型检查并行的全量复跑全部通过。失败日志保留，未修改这些页面或放宽断言；目前不能据此断言其在所有机器上均无时序波动。
- 这次没有重新执行真实 Provider smoke、生产并发饱和压测或部署验收；本机端口测试使用合成服务，不产生模型账单。
- 日志仍以固定 64 KiB 缓冲区校验完整文件/旧前缀，保留原地改写检测。只保留和解析新增内容，但总读取量仍随文件大小增长。
- SQLite 全历史聚合仍同步执行：本次 60,000 暴露约 228 ms；256 KiB Qwen 冷分词约 165 ms。修复消除了上述六项重复工作/生命周期问题，不代表主线程计算已全部迁移到 worker。若实测并发延迟超标，下一步评估有界 worker 队列或可修订的增量汇总，而非截断历史。
- 首次升级回填索引、排序键和估算字典，需要读取历史数据；迁移不自动 VACUUM。数据库仍随需保留的历史增长，释放页可被后续写入复用。
