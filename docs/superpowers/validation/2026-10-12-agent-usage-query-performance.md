# 用量查询投影与副本清理验证

日期：2026-10-12。仅本地合成 SQLite，没有生产数据库、真实 Provider、外部业务请求或部署。

## 同一数据集的查询对比

命令：`pnpm exec tsx scripts/benchmark-usage-queries.ts`。Node.js 22.16.0，磁盘 WAL，查询连接页缓存 8 MiB。数据为 2,000 个请求、200,000 条 exposure 和 200,000 条对话分片；合并后输入计数为 20,000 行。比较同一工作树中的明细查询路径与投影查询路径，以下为各三次热读中位数，不是原 Git HEAD 的完整前后对比，也不是生产 p95。

| 查询 | 明细路径 | 投影路径 |
| --- | ---: | ---: |
| 累计输入排名 | 1,133.44 ms | 253.85 ms |
| 观测内容排名 | 779.58 ms | 164.73 ms |
| 模型汇总与趋势 | 21.07 ms | 10.95 ms |

脚本逐项比较两条路径的完整排名及汇总／趋势结果；只有查询时间戳被忽略。结果一致。临时数据库、WAL 及目录均在 finally 中删除。

## 回归覆盖与限制

回归覆盖无关写入不失效、跨修订合并在途请求、30 秒旧快照边界、人工刷新、删除 generation、持久化对账及过期提交拒绝、模型／日期口径、迟到与修订首项、估算引用保护、去重／撤销身份和重复哈希清理。已准备的排名禁止读取 exposure，已准备的用量禁止重载账本；未准备范围保留原查询。

提交前复审修复两处边界：首次升级的建表、历史任务登记和触发器安装改为同一事务，避免中断重启后历史用量漏算；超时 Worker 保留退出 Promise，确认线程退出前不启动替代线程，关闭时也等待已请求终止的线程。两项回归均先复现失败再通过。原生 SQLite 调用可能延迟线程实际退出，因此 30 秒约束请求等待，不承诺在该时刻释放原生查询快照。

当前工作树验证：`pnpm exec vitest run --maxWorkers=2` 为 101 个文件通过、1 个跳过，1,356 个用例通过、18 个跳过；`pnpm typecheck`、`pnpm build`、`git diff --check` 通过。基准脚本也通过独立类型检查，沿用仓库的 `skipLibCheck` 设置。没有执行真实 Provider／外部集成烟测。默认高并发全量首轮曾暴露旧迁移／响应 fixture 和投影失效问题，已修复；期间未修改 Provider 扩展行为，相关测试单独复核通过，限制为两个 Worker 的最终完整运行通过。

旧计量 payload 与重复哈希按持久化主键游标清理，独立于较慢的统计回填。清理保留统计和证据，释放空间供 SQLite 复用；不自动 VACUUM。新投影和索引也需要磁盘空间。初次后台回填、真实低带宽宿主上的冷读和并发 p95 尚需目标环境验证，不能从该合成结果推导截图中约 18 分钟请求已在生产恢复到秒级。
