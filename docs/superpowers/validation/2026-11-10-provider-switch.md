# Agent Core 切换验证（2026-11-10）

范围：管理界面为 Agent 配置的能力随 Agent 保留；不隐式启用主机全局插件。不提交、部署或修改运行中的业务数据。

## 最终插件语义

插件是完整原生安装单位，不拆解成独立 Skills、MCP 或 Hook。已删除 DeepSeek 专用的包拆解、Workspace 插件投影和插件 MCP 注入分支。

切换前按完整插件标识（含 marketplace）寻找目标 Core 已发现的原生版本。成功后复用现有原生安装器，将完整包安装到隔离的 Provider Home，并写入该 Core 的插件注册、缓存及启用配置。只迁移 Agent 明确选择的插件，不因目标目录有其他插件而启用它们。不根据展示名称猜测替代插件，也不自动下载未知版本。

目前项目的原生扩展管理仅接入 Codex、Claude Code。Hermes、DeepSeek 尚未接入这一管理流程；目标没有匹配原生版本或安装适配时返回 `agent_extension_incompatible`，保留原 Agent 配置。不能把 Skills/MCP 拆解当成原生插件安装成功。独立 Hook 不跨 Core 转换。

参考原生格式：[Hermes 官方插件说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins)、[DeepSeek 官方安装说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/python-sdk.md)。两者分别使用原生插件注册及 DSH bundle/profile 安装流程；这些文档不构成本项目已实现对应安装适配的证明。

## 行为覆盖

- 四个已支持 Core 的 12 个有向切换组合：Agent 身份、Workspace 路径及文件、Session 和历史 Run 保留，原生执行上下文独立。
- 独立 Skills 在每种目标 Core 的既有目录规则下投影；独立 MCP 在全部 12 个方向保留加密凭据、会话参数和工具过滤。
- Codex ↔ Claude 使用目标原生插件版本，验证 Hook、命令、MCP 配置、实现文件完整保留，原生缓存及启用配置正确；停用、重新启用和切回原 Core 后选择仍有效。
- 无目标原生安装时，即使插件只有 Skills，也拒绝切换；停用的选择跨 Core 保留，不自动重新启用。
- 缺失原生来源的插件允许从 UI 停用，但不能重新启用。
- 指令、RTK 的 Core 支持声明由预检和管理 UI 共用；四个 Core 的 RTK 解析不修改已保存的设置。
- 模型策略按 Core 保存；队列、活动 Run、维护操作和预检期间配置变化有保护。
- 新上下文重置不销毁缓存的旧原生会话；存储清理处理 Session 的全部上下文；MCP 观测凭据及历史统计按执行上下文归属。
